# 04 · 风险与合规

**版本**：v1　**日期**：2026-10-08
**注意**：本文是**工程视角的风险清单，不是法律意见**。涉法事项请找律师。

## 1. 法律定性：这个项目是什么

| 行为 | 定性 | 风险 |
|---|---|---|
| **免费发放**代币给公众 | 不构成"融资" | **低** |
| 向公众**收钱**发币 | 非法集资 / 42 号文 | **红线，本项目不做** |
| 代币**可自由交易** | 定性转灰 | 中 |
| 代币 + **收益暗示** | 可能构成证券性质 | 中高 |
| 代币 + **上 DEX 建池** | 明显升高 | 本轮不做 |

**本项目的边界（必须守住）**：

1. **不向用户收一分钱**——这是法律上最关键的一条，也是本系统架构不变量 I1 的直接来源
2. **本轮不发 LP、不上 DEX**
3. **不做任何收益暗示**：页面和推文**不得出现**"投资""涨幅""翻倍""早期入场""价值"等字样
4. **不承诺代币价格或兑换率**
5. 页面显著位置写明：**本代币不可转让、不构成投资标的**

> ⚠️ 一旦违反第 1 条，性质从"免费活动"变成"非法集资"，**没有中间地带**。

### 收集了什么

| 数据 | 来源 | 用途 | 保留期建议 |
|---|---|---|---|

| X 用户名 | OAuth | 展示/客服 | 同上 |

## 4. 中国监管语境（2026 年现状）

### 4.1 现行框架：境内禁止、境外严管

| 文件 | 时间 | 要点 |
|---|---|---|
| 《关于防范代币发行融资风险的公告》（七部委，即"9·4 公告"） | 2017-09-04 | 代币发行融资定性为非法公开融资 |
| **银发〔2026〕42 号**（八部门） | **2026-02-06** | 境内**严禁**任何形式 RWA 代币化活动；**为其提供托管、清算结算、中介、信息技术等配套服务，同样涉嫌非法金融活动** |
| **证监会公告〔2026〕1 号**《关于境内资产境外发行资产支持证券代币的监管指引》 | 2026-02-06 | 为"境内资产 → 境外发行"开了**有条件**的合法路径，需事前备案；**发行对象不得面向境内居民** |

**原则**：「相同业务、相同风险、相同规则」——代币化不改变融资/证券/外债的监管属性，
RWA 代币被"去其'币'属性、取其'证'功能"，纳入证券法律框架。

### 4.2 对本项目的具体含义

| 本项目的情况 | 判定 |
|---|---|
| 免费发放、不向公众收钱 | ✅ 不构成融资 |
| 代币可在市场交易 | ⚠️ 定性转灰 |
| **声称"以后可兑换成证券代币"** | ❌ **制造预期收益，可能被认定为类证券活动** |
| 面向**境内居民**做证券化相关表述 | ❌ **明确越线** |
| 境内做 RWA 代币化 / 为其提供技术服务 | ❌ **42 号文明确禁止** |

### 4.3 其他相关罪名

- **刑法第 266 条 诈骗罪**：以非法占有为目的、虚构事实骗取财物。
  **本项目真发放、可验证，不构成**；但若哪天决定不发或少发，就直接命中。
- **帮助信息网络犯罪活动罪**：若你帮别人的盘做推广，这条会落在你身上。

### 4.4 结论

**本项目的法律风险主要来自"未来改变主意"和"未来乱承诺"，而不是当前设计。**

所以技术方案里的"可验证"要求（公开发放 tx 签名、名单哈希）**同时也是法律保护**——
它们是你"没骗人"的唯一客观证据。

**红线补充**：**不得以任何形式暗示"未来可兑换证券化代币 / 上市交易 / 具备投资价值"。**
这句话对境内受众而言，对应的合规路径在法律上是被明确排除的——说了就是空头承诺 + 制造预期。

## 4.5 开源带来的额外风险与缓解

本项目将开源为模板（[ADR-0003](ADR/0003-开源与私有边界.md)）。这引入了**一类新的风险**：
**别人拿你的工具去作恶，会关联到你的署名。**

### 风险与缓解

| 风险 | 缓解 |
|---|---|
| 有人 fork 后做假空投 / 卷款 | **架构不变量 I1：系统不含任何收款功能**——从根上做不到 |
| 有人用它伪造进度条骗人 | **I2/I3：不存在虚假展示组件，统计只从 DB 实时查** |
| 有人声称发货却不发 | **I4：txHash 强制入库 + 公开导出**，链上可对账 |
| 有人拿它做非法集资 | **I1 直接排除**——收不了钱就不可能构成非法集资 |
| 被认定为"为境内非法代币活动提供技术服务"（42 号文） | **I1–I5 使工具定性为"防骗基础设施"**；README 明确边界；SECURITY.md 提供滥用上报路径 |
| 署名被恶意关联 | README 加免责声明：按"现状"提供，作者不对使用者行为负责；保留滥用上报与处理记录 |

### 核心判断

> **这五条不变量既是伦理约束，也是对作者最有效的法律保护。**
>
> 一个「收不了钱、造不了假、必须真发货」的工具，很难被认定为"为非法活动提供技术便利"。
> **把"不可作弊"做成架构约束，而不是文档里的一句提醒**——这是开源这个工具唯一安全的方式。

## 6. 技术风险

| 风险 | 影响 | 已采取的对策 |
|---|---|---|
| 热钱包私钥泄露 | 钱包内全部资金丢失 | 只放 ~$77 的 BNB、视为可烧毁、签发分离、不入码不入库 |
| **管理后台被入侵** | 攻击者可改基础额、取消领取、导出用户名单 | SIWE **白名单**（非密码）、`/admin` 不在导航、HMAC 会话 + 短有效期、**无提款功能（I1）**、**不能改统计/已发放金额**、全动作审计 |
| 管理员钱包私钥泄露 | 同上 | 用**独立于热钱包**的钱包做管理员；该钱包不放资金 |
| 被脚本撸光预算 | 预算几小时内耗尽 | 延迟发放 + 总量上限 + 限流 + 停机开关 |
| 重复支付 | 多付资金 | 租约 + 部分唯一索引 + nonce 对账 + **幂等** |
| RPC 单点故障 | 发放中断 | 建议用付费 BSC RPC；INFRA 类失败不消耗重试次数 |
| 崩溃导致漏付/重付 | 账实不符 | nonce 追踪 + receipt 轮询 + **SIGKILL 故障注入测试** |
| **nonce 覆盖** | 用同一 nonce 重发会覆盖掉一笔已成功的转账，导致某个用户没收到却记为 PAID | 未确认前**禁止**同 nonce 重发；对账以 nonce 为准 |
| **代币合约漏洞** | 被增发/后门 | 用 OpenZeppelin 标准合约，**无 owner、无 mint、无 pause、无黑名单**，源码 BscScan 验证 |
| BSC gas 暴涨 | 成本上升 | 已实测需涨 100 倍才追平原 Solana 方案；且设了 `MAX_GAS_SPEND_WEI` 硬上限 |

## 7. 声誉风险（这一条最重要）

**任何人用公共 RPC 加一条命令，就能拆解你的链上行为**——这个成本已经接近零。

| 如果你造假 | 后果 |
|---|---|
| 假进度条 | 一算就穿帮（真实数 vs 展示数） |
| 假买单 | 机器生成地址的指纹（前缀+后缀）是可统计检测的 |
| 不发放 / 少发放 | 链上转账数对不上 PAID 数，一眼可见 |

**唯一有效的辩护是：一切都是真的，而且是可验证的。**

具体做法（写进产品，不是写在嘴上）：
- 公开**发放交易的 tx 签名**
- 公开**领取名单的哈希**（可校验完整性，又不泄露隐私）
- 页面统计**全部来自数据库实时查询**，不写死
