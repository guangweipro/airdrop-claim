## M0b 说明：GitHub 免费计划的限制（已解决）

实测结论：**免费个人计划的私有仓库不支持分支保护 / rulesets / secret scanning / code scanning。**

```
$ gh api -X PUT repos/.../branches/main/protection
{"message":"Upgrade to GitHub Pro or make this repository public to enable this feature.","status":403}
```

| GitHub 功能 | Free 私有仓库 | 解决方式 | 状态 |
|---|---|---|---|
| **分支保护 / rulesets** | ❌ | **转 public**（或 GitHub Pro $4/月） | ✅ 已解决 |
| secret scanning / push protection | ❌ | CI 里的 gitleaks + **本地 pre-push 钩子** | ✅ 补偿 |
| CodeQL / code scanning | ❌ | CI 里的 Semgrep；`codeql.yml` 带守卫，public 后自动生效 | ✅ 补偿 |
| Dependabot 告警与安全更新 | ✅ 免费 | — | ✅ 已启用 |

**为什么当时不能含糊**：项目规范把分支保护定为"**唯一一个不依赖作者诚实**"的约束。
私有仓库状态下那一条恰恰缺失——没有东西拦着直接推 main，也没有东西能向别人证明没被绕过。

**最终选择**：转 public。代价是**整套文档必须先脱敏**（业务策略、账号数据、第三方项目分析都不属于工程文档），
并清理 git 历史。这一步已在转 public 之前完成。

> **pre-push 钩子比 GitHub push protection 更早**：密钥根本没离开本机，
> 而不是推上去之后才告警。它是本项目在 secret scanning 不可用期间的主要防线。

## 分阶段放量（M10 内部）

不要一次开 1000 人：

```
10 人   → 链上对不对？发得出去吗？
          停 24 小时，人工看这 10 个账号像不像真人
100 人  → 成功率？异常率？预算消耗速度对不对得上是 $0.002/人？
          停 24 小时，复核女巫情况
1000 人 → 全量
```

**每阶之间必须有人工检查点**，这是防"一夜被撸光"的最后一道闸。

## 明确不做的验收项（本轮）

DEX 流动性、二级市场、代币转让、代币在自有生态内的消费闭环、Referral、多链、移动端。
不列入验收，也不在实现时顺手做（对应你的"禁止擅自扩大改动范围"）。

## 单人与自审问题

你是单人开发，按你的规范 §6.4 不能自批：

- 每个里程碑完成后**冷却 ≥ 4 小时**再进入下一阶段
- **M6（合约 + 签发）**、**M7（链上发放）**、**M9（部署）** 是高风险节点，需独立复审
- 若 Codex 会话仍在线，**可互为复审方**——它写、我审，或我写、它审
- 高风险节点保留**书面检查单**，逐条打勾，不凭记忆
