# 01 · 技术方案（BSC / EVM 版）

**版本**：v3（Solana → BSC 切换后）　**日期**：2026-10-08
**链选择依据**见 [ADR-0001](ADR/0001-为什么选-BSC-而非-Solana.md)

---

## 1. 目标与非目标

**目标**：一个可验证、不会被滥用烧光预算的领取系统。用户 X 登录 → 连钱包签个名（SIWE）
→ 真的收到 BEP-20 代币。运营方承担全部 gas，用户零 BNB 门槛。试点 ≤ 1000 人。

**非目标**：不向用户收任何钱；不做预售；不承诺代币市场价值；本轮不做 DEX 流动性。

---

## 1.5 架构不变量：本系统「不可作弊」

本项目计划**开源为模板**（见 [ADR-0003](ADR/0003-开源与私有边界.md)）。
因此下列五条不是"建议"，是**硬性架构约束**，任何实现不得绕过：

| # | 不变量 | 落地要求 |
|---|---|---|
| **I1** | **系统不含任何收款功能** | 无预售、无支付接口、无资金归集、**代码中不存在托管地址常量** |
| **I2** | **不含任何可配置的虚假展示组件** | 没有假进度条、没有假买单滚动条。想造假必须另写模块，而不是改配置 |
| **I3** | 所有对外统计**必须**来自数据库实时查询 | `/api/stats` 只查库，**无任何写死的数字** |
| **I4** | 发放 `txHash` **强制入库** + 提供公开导出 | 声称发货必须真的发货，任何人可独立核验 |
| **I5** | **SIWE 签名校验不可通过配置关闭** | 保留地址归属证明，去掉最省事的糊弄路径 |

**为什么这五条是硬约束**：

1. **I1 从根上排除了"卷款跑路"这一类用法**——不能收钱，就无法构成非法集资。
   这既是伦理约束，也是**对作者最有效的法律保护**（42 号文把"为境内非法代币活动提供信息技术服务"
   也列为违规；一个收不了钱的工具很难被认定为"为非法活动提供技术便利"）。
2. **I3 + I4 让"造假"在架构上没有位置**——不是靠文档里写"请不要造假"。
3. 这五条把项目的定性从「发币工具」变成「**防骗基础设施**」。
4. **管理后台同样受这五条约束**（见 §7.5）：后台能改基础额，但**不能改统计数字**（I3）、
   **不能改已生成 Claim 的金额**（否则破坏 I4 的对账等式）、**没有提款功能**（I1）。

> **实现期检查**：每条不变量都要有一个测试守住，防止后续改动悄悄破坏它。
> 见 §12 测试策略的「不变量测试」。

## 2. 系统架构

```
浏览器
  ├─ X OAuth 2.0 PKCE ──→ 只取 x_user_id（不核关注）
  ├─ wagmi/viem 连接钱包 + SIWE 签名 ──→ 证明地址归属
  └─ POST /api/claim/submit
          │
          ▼
   ┌─ Cloudflare Workers / Pages (OpenNext) ──────────┐   ← 免费，无运维
   │  Next.js App Router 进程  ← 永不接触热钱包私钥    │
   │    ├─ 校验 SIWE（nonce 一次性 + 域绑定 + TTL 300s）│
   │    ├─ 去重（x_user_id 唯一 / wallet 唯一）         │
   │    ├─ 限额（总量 / 每 IP / 领取窗口 / 停机开关）    │
   │    └─ 写 claims 行 status=PENDING                 │
   └────────────────────┬──────────────────────────────┘
                        │ Prisma driver adapter
                        ▼
   ┌─ 托管 PostgreSQL（Neon / Supabase）───────────────┐   ← 免费档
   │  claims / tranches / attempts / nonce / 审计      │
   └────────────────────┬──────────────────────────────┘
                        │ 直连
                        ▼
   ┌─ 本机批处理脚本（每天跑一次）──────────────────────┐   ← $0
   │  签发进程：唯一持钥方，私钥不出本机                 │
   │    ├─ 取已到期且解锁条件满足的 tranche              │
   │    ├─ 组交易 → 策略校验 → 预算守卫 → 签名 → 广播     │
   │    ├─ nonce 追踪 + receipt 轮询对账                 │
   │    └─ 回写 status=PAID + tx_hash                   │
   └───────────────────────────────────────────────────┘
```

**部署依据见 [ADR-0002](ADR/0002-托管与部署方案.md)。**

### 三个关键设计

**① 领取 ≠ 立即到账。** 领取只入库，发放按批次延迟执行，留出反滥用窗口。

**② 签发分离。** Web 层是暴露面最大的组件，**永不持有私钥**。
私钥只在本机批处理脚本里，**不要放进 Cloudflare**——Cloudflare 支持的签名算法只有
ECDSA P-256/384/521，**WebCrypto 不支持 secp256k1**（BSC 用的正是它），放上去没有安全收益。

**③ 试点期不需要常驻服务。** 延迟批量 + ≤1000 人 = **每天跑一次脚本就够**。
代码写成"跑一遍"的函数，将来规模上去再套循环切换成常驻，**不用重写**。

## 3. 关键技术决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | **BSC（EVM）**，非 Solana | [ADR-0001](ADR/0001-为什么选-BSC-而非-Solana.md)：成本差 89 倍 + 可复用既有 EVM 栈 |
| 2 | **1 个领取人 = 1 笔交易**（不做批量） | BSC 上批量只省约 $0.02/1000，却引入三类复杂度 |
| 3 | SIWE（EIP-4361），**不用** SIWS | 成熟标准；`ZeroDiamond` 已跑通生产 |
| 4 | ERC-20 **固定总量 + 无 owner + 无 mint 函数** | 合约在 BscScan 开源验证，"不可增发"可被任何人独立核验 |
| 5 | Postgres `SKIP LOCKED` 做队列，**不用 Redis/BullMQ** | 第二个 job 状态存储是"重复支付"的经典成因 |
| 6 | 试点期用**每日一次性批处理**，不用 timer 当持续 worker | timer 做持续 worker 会重叠运行、无对账窗口；但延迟批发放只需每天跑一次（见决策 15） |
| 7 | **nonce 追踪 + receipt 轮询**，不用 `waitForTransactionReceipt` 一把梭 | 显式区分"已广播/已上链/被丢弃"，这三者处置不同 |
| 8 | **不存储 X access token** | `/me` 之后不再调用 API；也不请求 `offline.access` |
| 9 | 域（`domain`/`redirect_uri`）**来自配置，不来自请求 Host 头** | 防域欺骗 |
| 10 | **有管理后台，但用 SIWE 白名单保护**（不用密码） | 单人有日常运营需求；复用已在建的 SIWE，**零新增凭据**；**不做角色系统** |
| 11 | 策略校验放在签发进程内（不做独立签名守护进程） | 见 §5.4 取舍 |
| 12 | **Web 层放 Cloudflare Workers/Pages**（OpenNext） | 免费、零运维、全球加速 |
| 13 | **数据库用外部托管 Postgres，不用 D1** | D1 是 SQLite，**没有 `SKIP LOCKED`**，本方案依赖它 |
| 14 | **签发不放 Cloudflare**，试点期本机批处理 | secp256k1 不在 WebCrypto 支持范围，放上去无安全收益；且免费版 10ms CPU 不够签名 |
| 15 | 试点期**不做常驻进程**，每天一次性批处理 | 1000 人 + 延迟发放不需要守护进程；代码形态不变，将来套循环即可 |

## 4. 领取流程

**含公开传播机制**：

```
① GET  /api/auth/x/start     → 生成 PKCE verifier + state，302 到 X 授权页
② GET  /api/auth/x/callback  → 换 token → GET /2/users/me → 建会话 Cookie（HMAC 签名）
③ GET  /api/claim/code       → 为用户生成一次性领取代码（如 AC-8F3A21）
④ 用户到 X 上【引用活动推文】，推文内容里带上该代码
⑤ POST /api/claim/verify-tweet（提交推文链接）
      后端一次 API 调用核验四件事：
        ✓ referenced_tweets 含 {type:"quoted", id: CAMPAIGN_POST_ID}
        ✓ text 含该用户的一次性代码
        ✓ author_id == 登录的 x_user_id          ← 防偷别人的推
        ✓ 该推文 ID 未被使用过                    ← 防复用
⑥ POST /api/claim/nonce      → 签发一次性 SIWE nonce（入库，TTL 300s）
⑦ 前端 wagmi signMessage(SIWE 消息)
⑧ POST /api/claim/submit     → 验签 + 去重 + 限额 → 写 PENDING
```

**第 ④⑤ 步是传播机制的核心**——它把"领取"变成一次必须在 X 上公开发生的动作，
因此每次领取都会触达领取者自己的受众。
**没有这一步，一个纯表单式的领取页不会带来任何自然曝光。**

**分级奖励**：`GET /2/users/me` 时一并取 `user.fields=public_metrics`，用 `followers_count`
定奖励倍数（<100 → 1×，100–1k → 2×，1k–10k → 5×，>10k → 10×）。**不额外花钱**（同一笔用户查询）。

**门槛**：X 账号注册 ≥ 30 天、发帖 ≥ 10。

**SIWE 消息**（EIP-4361 标准格式）：`domain` / `address` / `uri` / `nonce` / `chainId` / `issuedAt`。
服务端校验签名（`siwe` + `viem.verifyMessage`）并核对 domain、nonce、chainId。

## 5. 发放流程（payout 进程）

### 5.1 主循环

**写成"跑一遍"的幂等函数**，本机每天执行一次；将来规模上去外面套一个循环即变成常驻：

```
runOnce():
  1. 若 PAYOUTS_PAUSED=true → 直接返回（不发任何东西）
  2. 取「已到期且解锁条件已满足」的 tranche 一批（默认 20）
  3. 第 2/3 期发放前：重新核验那条引用推文是否仍在（删推即取消资格）
  4. 逐条：CAS 加锁置 LOCKED（幂等，绝不重复支付）
  5. 逐条组交易 → 策略校验 → 预算守卫
  6. 签名（记录 nonce）→ 广播 → 轮询 receipt
  7. 成功：写 tx_hash + status=PAID
  8. 失败：分类 → 见 §5.5
```

**为什么可以"跑一次"而不用常驻**：领取与发放是**两件事**，中间隔着 T+24h。
单次运行 + 租约 + 幂等约束，重复跑安全。详见 [ADR-0002](ADR/0002-托管与部署方案.md) §理由 3。

**第 3 步的意义**：因为发放是延迟的，"发完就删推"这条捷径自然失效。
**第 2 步的分期**是抗取关机制——解锁条件绑定的是你自己的平台动作（签到 / App 使用 / 直播），
**不依赖 X API 核验关注**：X API 没有"判断 A 是否关注 B"的布尔端点，只有按**返回用户数计费**的列表端点，
逐人核验意味着对每个领取者做一次全量翻页，成本不可行。
因此把留存条件绑定到**自己平台内的动作**，而不是"关注"这个脆弱且昂贵的指标。

### 5.2 单笔交易的内容

对一个 claim 发一笔 `transfer`：

```
to    = 代币合约地址
value = 0
data  = transfer(claim.wallet, claim.amount)
```

**没有 ATA、没有账户租金、没有交易体积限制。** 这是 EVM 相比 Solana 最直接的简化。

### 5.3 为什么不做批量转账

BSC 上 51000 gas ≈ $0.000002。批量 10 笔省 90% 手续费 = **$0.0000018/人 ≈ $0.0018/1000 人**。
**省下来的钱是零头，换来的是部分失败、重试归因、预算归属三类复杂度。不值得。**

单笔还让对账等式成立：**链上 transfer 数 == PAID 数**。

### 5.4 策略校验（signer policy）

签发前对交易做白名单校验，**拒绝任何不在允许集合里的内容**：

- ✅ **允许**：`to == TOKEN_CONTRACT` 且 `value == 0` 且 `data` 解码为
  `transfer(recipient, amount)`，其中 `recipient == 该 claim 的钱包`、`amount == 该 claim 的额度`
- ❌ **拒绝**：`to != TOKEN_CONTRACT`（防被诱导调任意合约）
- ❌ **拒绝**：`value > 0`（防把 BNB 转出去）
- ❌ **拒绝**：selector 不是 `transfer`（防误调 `approve` / `transferFrom` / `owner` 类函数）
- ❌ **拒绝**：`amount > 单人额度`、`recipient` 不在本批 claim 集合内
- ❌ **拒绝**：`gasLimit` 或 `maxFeePerGas` 超过上限

> **取舍说明**：复核建议做成独立签名守护进程（unix socket + 网络隔离，把私钥与网络完全隔离）。
> **对 1000 人、热钱包只放 ~$20 的试点，我判断过重**——多一个常驻组件、一套 IPC 协议、一类新故障面。
> 本轮采用"进程内策略函数 + 单元测试覆盖"，拿到收益的 80%。
> 若试点扩大或热钱包余额上升，**再升级**。记入技术债。

### 5.5 失败分类（关键：不是所有失败都该重试）

| 类别 | 例子 | 处理 |
|---|---|---|
| **INFRA** | RPC 超时、`insufficient funds for gas`、`nonce too low` 竞态 | **不增加 attempts**，退避重试；连续多次触发熔断 + 告警 |
| **DATA** | 地址非法、金额超限、合约 revert（`ERC20InsufficientBalance`） | 直接置 `FAILED` + 告警，不重试 |
| **UNKNOWN** | 已广播但未拿到 receipt | **不动状态**，交给对账裁决（§5.6） |

### 5.6 对账（reconcile）—— 崩溃恢复的正确性全靠这里

EVM 的 nonce 是天然的对账锚点：

- 启动时扫描所有 `LOCKED` 且租约过期的记录
- 对每条已记录的 `nonce` 与 `tx_hash`：
  - `eth_getTransactionReceipt(hash)` 有结果 → 置 `PAID`
  - 无结果，但账户 `latest` nonce **已越过**该 nonce → 说明被替换/丢弃 → 退回 `PENDING`
  - 无结果，且 `latest` nonce 未越过 → **可能仍在内存池** → 等待，不重发
- **禁止**在没有确认的情况下用同一 nonce 重发（会造成替换竞态）

### 5.7 预算守卫

```
发放前：spent + 本笔预估 > MAX_GAS_SPEND_WEI  →  停止整轮 + 告警
```

BSC 上没有"预留/退回租金"的问题，预算模型因此**大幅简化**——只有 gas，而且极小。

## 6. 数据模型（Prisma / PostgreSQL）

```prisma
enum ClaimStatus { PENDING LOCKED PAID FAILED CANCELLED }
enum AttemptStatus { RESERVED SENT EXPIRED FAILED }

/// 活动配置。**可变，但只影响之后的新领取**——已生成的 Claim 金额在下单时已冻结。
model CampaignConfig {
  id               Int      @id @default(1)   // 单行表
  baseClaimAmountWei String                    // 基础领取额（管理员可改）
  campaignOpen     Boolean  @default(true)
  payoutsPaused    Boolean  @default(false)
  adminAddress     String                      // 管理员钱包（小写规范化）
  updatedAt        DateTime @updatedAt
  updatedBy        String?
}

model XIdentity {
  id               String   @id @default(cuid())
  xUserId          String   @unique          // 1 账号 = 1 次
  handle           String
  accountCreatedAt DateTime?
  followersCount   Int?
  claim            Claim?
  createdAt        DateTime @default(now())
}

model Wallet {
  id        String   @id @default(cuid())
  address   String   @unique                 // 小写规范化后唯一；1 钱包 = 1 次
  claim     Claim?
  createdAt DateTime @default(now())
}

model Claim {
  id            String      @id @default(cuid())
  xIdentityId   String      @unique
  walletId      String      @unique
  claimCode     String      @unique           // 一次性代码，用户发进推文
  tweetId       String      @unique           // 核验通过的引用推文 ID，防复用
  tierMultiplier Int                        @default(1)  // 按粉丝数分级
  totalAmountWei String                      // 领取时冻结，不随后端配置漂移
  status        ClaimStatus @default(PENDING)
  tranches      PayoutTranche[]
  createdAt     DateTime    @default(now())
  @@index([status, createdAt])
}

// 分期发放：30% 立即 / 30% T+30d / 40% T+90d（设计依据见文档 07 §4.3）
model PayoutTranche {
  id           String        @id @default(cuid())
  claimId      String
  seq          Int                            // 1 | 2 | 3
  unlockAt     DateTime                       // 解锁时间
  unlockKind   String                         // IMMEDIATE | CHECKIN | APP_USE | LIVE
  amountWei    String
  attempts     PayoutAttempt[]
  status       ClaimStatus   @default(PENDING)
  @@unique([claimId, seq])
  @@index([status, unlockAt])
}

model PayoutAttempt {
  id             String        @id @default(cuid())
  claimId        String
  leaseToken     String        @unique
  leaseExpiresAt DateTime
  nonce          Int?                          // EVM 对账锚点
  txHash         String?       @unique
  gasLimit       BigInt?
  maxFeePerGas   BigInt?
  status         AttemptStatus @default(RESERVED)
  attempts       Int           @default(0)
  errorCode      String?
  errorKind      String?                       // INFRA | DATA | UNKNOWN
  createdAt      DateTime      @default(now())
  @@index([claimId, status])
  @@index([status, leaseExpiresAt])
}
```

> **关键约束**：`PayoutAttempt` 需要一条**部分唯一索引**
> （同一 claim 至多一条非终态 attempt），这是"恰好一次"的**数据库级**保证。
> Prisma 需用原生 SQL 迁移补这条索引。
>
> **地址必须小写规范化后入库**——EVM 地址有 checksum 大小写变体，
> 不做规范化会出现"同一个地址算两个钱包"的漏洞。

`SiwsNonce`（改名为 `AuthNonce`）、`AuditLog` 两张表照旧。

## 7.5 管理后台（受保护）

### 认证：SIWE 白名单，不用密码

```
① 访问 /admin（不放在首页导航里）
② 连接钱包 → POST /api/admin/nonce 拿 nonce
③ SIWE 签名 → POST /api/admin/login
④ 服务端校验签名 + 【地址 === CampaignConfig.adminAddress（小写规范化）】
   → 不是白名单地址 → 401，且不泄露"地址是否存在"
⑤ 通过 → 下发 HMAC 签名会话 Cookie（HttpOnly + Secure + SameSite=Lax）
```

**为什么用 SIWE 白名单**：
- **零新增凭据**——复用已在建的 SIWE，没有密码要管、要轮换、要防爆破
- 签名可验证，地址可审计
- **单人项目不需要角色系统**——一个管理员地址就是全部权限模型

**可选叠加**：Cloudflare Access（把认证挡在应用之前）。但**SIWE 白名单是必须的**，Access 只是额外的纵深。

### 后台能做什么、不能做什么

| 能做 | 不能做 |
|---|---|
| 看实时统计（**与公开接口同源**） | ❌ **改统计数字**（破坏不变量 I3） |
| **改基础领取金额**（只影响之后的新领取） | ❌ **改已生成 Claim 的金额**（破坏对账等式） |
| 开关领取窗口 / 停机开关 | ❌ **提款**（本系统无此功能，不变量 I1） |
| 取消违规领取（置 `CANCELLED`） | ❌ 改用户钱包地址 |
| 导出名单 + txHash | ❌ 删除已发放记录 |

### 金额冻结规则（**不可妥协**）

```
❌ 错误：Claim 只存引用，发放时读当前配置
   → 改配置会让【已领的人】金额跟着漂移 → 链上转账数与 PAID 数对不上

✅ 正确：领取时算好并冻结
   Claim.totalAmountWei = baseClaimAmountWei × 通道倍数 × 粉丝分级倍数
   → 之后改配置，只影响【还没领的人】
```

### 审计

**每一个管理动作写 `AuditLog`**：谁（管理员地址）、何时、改了什么、旧值→新值。
`updatedBy` 记录在 `CampaignConfig` 上。

### 开源模板中的处理

- **`ADMIN_ENABLED=false` 默认关闭**
- README 明示：**启用前必须自己加上认证**，并替换 `adminAddress`
- 理由：模板会被别人用；一个没认证的管理后台是**署名风险**

## 9. 代币合约（BEP-20）

```
OpenZeppelin ERC20，构造时一次性 mint 全量到金库
  ├─ ❌ 无 mint 函数        → 总量永久固定
  ├─ ❌ 无 Ownable          → 没有 owner 可以后门
  ├─ ❌ 无 pause / 黑名单
  └─ ✅ 源码在 BscScan 验证公开
```

**这比 Solana 的"已撤销 mint authority"是更强的信任信号**——
任何人都能在 BscScan 上独立核验"不可增发"，不需要信任你的声明。

**代币参数（env 配置，默认值待你确认）**：
总量 1,000,000,000、精度 **18**（ERC-20 标准）、每人 100,000。

## 10. 安全控制（不可裁剪）

| 控制 | 做法 |
|---|---|
| 私钥不入码不入库 | 仅 `OPERATOR_PRIVATE_KEY` / `OPERATOR_KEYSTORE_PATH`；`.env` gitignore；`.env.example` 只有键名 |
| gitleaks 自定义规则 | 默认规则**看不出来** 0x 私钥与 keystore JSON，必须加自定义规则 |
| 预算硬上限 | `MAX_GAS_SPEND_WEI`；超限即停整轮 |
| 总量硬上限 | `MAX_TOTAL_CLAIMS` |
| 限流 | 每 IP 5 次/分；X 账号前缀簇限额 |
| 幂等 | claim 级租约 + 部分唯一索引 + `txHash` 唯一 |
| 重放防护 | nonce 一次性 + TTL + 域绑定 + **chainId 校验** |
| 地址规范化 | 一律小写存储 |
| 停机开关 | `PAYOUTS_PAUSED`，一轮内生效（**要有断言测试**） |
| 管理后台 | `/admin` 不放在首页导航；**SIWE 白名单**（`adminAddress` 小写规范化比对）；不做密码、不做角色系统 |
| 管理会话 | HMAC 签名 Cookie，HttpOnly + Secure + SameSite=Lax；**短有效期** |
| 管理动作审计 | 全部写 `AuditLog`（谁 / 何时 / 旧值 → 新值） |
| 管理后台**不可** | 改统计数字（I3）、改已生成 Claim 金额、提款（I1）、删记录 |
| 开源模板 | `ADMIN_ENABLED=false` 默认关闭 |
| 日志脱敏 | 断言日志中不出现 `Bearer `、私钥、access token |
| 热钱包定位 | 只放 ~$20 的 BNB（够 1000 人 gas），视为**可烧毁** |

## 12. 测试策略

| 层 | 内容 | 进 CI |
|---|---|---|
| **不变量测试** | 断言 §1.5 的五条不变量**无法被绕过**：代码中不存在收款路径；`/api/stats` 查询源是 DB；`txHash` 非空约束生效；SIWE 校验无关闭开关 | ✅ |
| 单元 | SIWE 验签向量、nonce 生命周期、claim 状态机、预算算术、**signer 策略白/黑名单**、失败分类 | ✅ |
| 集成 | 唯一约束、部分唯一索引、"恰好一次"、10 并发只有 1 条成立、租约过期接管、停机开关、地址大小写规范化 | ✅（postgres service） |
| **管理后台** | 非白名单地址登录被拒；**改基础额不影响已有 Claim 的冻结金额**；无提款路由存在；每个管理动作写审计；`ADMIN_ENABLED=false` 时 `/admin/*` 全部 404 | ✅ |
| 链上（**BSC 测试网 Chapel, chainId 97**） | 端到端发放、**SIGKILL 故障注入**、nonce 竞态、余额耗尽熔断 | ❌ **不进 CI** |

**测试网测试不进 CI 的理由**：把测试网私钥放进 GitHub Secrets 本身就是风险。本地 + 夜间跑。

> **最重要的一条测试**：在"已签名未广播"和"已广播未确认"两点 `SIGKILL`，
> 重启后断言 **每个 claim 链上恰好只有一笔 transfer**，
> 且**没有因为重发同一 nonce 而覆盖掉一笔已成功的转账**。
> 没有这条测试，§5.6 的对账设计就只是"声称"，不是"事实"。

**硬性纪律**：测试代码路径**永不签名**；dry-run 只调 `eth_call` 模拟；
测试网 setup 里硬断言 **chainId ≠ 56（主网）**。

## 13. 明确否决的做法

1. 批量转账（§5.3）
2. BullMQ + Redis 队列
3. 用高频 timer 当**持续** worker（试点期的每日一次性批处理是另一回事，见决策 15）
4. 存 X access token / 请求 `offline.access`
5. 多 worker 实例（用 Postgres advisory lock 消灭竞争类）
6. 从请求 Host 头推导 domain / redirect_uri
7. **无认证的**管理后台（放首页导航 / 用密码登录 / 做角色系统）——受 SIWE 白名单保护的后台见 §7.5
8. **改已生成 Claim 的金额**（会让链上转账数与 PAID 数对不上）
8. `waitForTransactionReceipt` 当唯一确认依据（超时后无法区分"丢弃"与"待确认"）
9. 未确认就用同一 nonce 重发
10. 用 `approve` + `transferFrom`（本项目根本不需要授权额度，多一个攻击面）
11. 代币合约里留 `owner` / `mint` / `pause` / 黑名单函数
12. 自动执行钱包聚集判定
13. 带奖励的邀请/推荐码
14. 把运营方私钥"临时"放进 Next.js 进程（**没有临时这回事**）
15. 用户自助改钱包地址
16. 在 Ethereum L1 上发（$161/1000，无任何优势）
